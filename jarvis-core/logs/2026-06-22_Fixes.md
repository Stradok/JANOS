## Current Architecture

```
User message
  → OrchestratorV2 (keyword route → LLM classify fallback)
    → Agent (agentic loop: think → tool → observe → repeat)
      → Tools (modules): spotify | browser | system_control | file_manager | etc.
        → ScreenReader.observe() → pyautogui screenshot → pytesseract OCR
          ⚠ pyautogui NOT installed → screenshots always fail → agents are BLIND
```

**Stack:**
- Server: FastAPI + Uvicorn, port 8000
- LLM: Ollama local — qwen2.5:7b-instruct (agents), gemma4:12b (router)
- Memory: SQLite (`jarvis_memory.db`) + ChromaDB (`chroma_db/`)
- Screens: 3 monitors — DP-1 2560×1080, DP-2 1920×1080 (primary), HDMI-1 1920×1080
- Session type: **Wayland** (not X11) — affects screenshot tools significantly
- Spotify: snap install at `/snap/bin/spotify`
- No vision model installed (no llava, minicpm-v, etc. in Ollama)

## Important Decisions

- **Email uses `system_control.open_url`** not `browser.open` — Playwright launches fresh Chrome with no session; `webbrowser.open()` uses user's real browser where they're logged in.
- **Spotify never uses browser** — `browser` removed from media agent tool list entirely.
- **D-Bus MPRIS2 via `dbus-send`** chosen as primary Spotify control (zero install, built-in on all D-Bus desktops).
- **`spotify:search:QUERY` URI** is the search fallback — registered handler confirmed (`spotify_spotify.desktop`).
- **Wayland blocks X11 tools** — `pyautogui`, `xdotool`, `xwd` all fail. Must use `grim` or GNOME D-Bus for screenshots.
